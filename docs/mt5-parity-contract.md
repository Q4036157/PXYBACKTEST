# MT5 成交级一致性契约

> 契约版本：`pxybacktest.mt5-parity.v1`
>
> 代码基线：PXYBACKTEST `40d85b7ef1feee0eb31b8ba96beb949bb2cbe9fd`
>
> 复核日期：2026-09-02
>
> 验证方式：`python -m pytest -q tests/test_mt5_parity.py`

## 目标

`mt5_native` 是 MetaTrader 5 Strategy Tester 的权威参考执行器；`mt5_compat`
是在 PXY 真实 Tick 回放内运行的独立执行器。两者不能因为总收益接近就称为一致，
必须在固定数据、固定 EA、固定参数、固定账户规格下按原始成交顺序比较。

## 固定测试向量

每个测试向量必须保存以下不可变身份，不保存账户密码或终端登录信息：

- EA 源码和 EX5 的 SHA256；
- 输入参数及其 SHA256；
- 品种、周期、开始/结束时间、测试模型；
- 初始资金、币种、杠杆、净额/对冲模式；
- 合约大小、点值、最小手数、手数步长、最小止损距离；
- PXYDATA 原始 Tick 快照 ID、清单哈希、来源和时区；
- MT5 终端版本、服务器名称和 Strategy Tester 报告 SHA256；
- PXY 策略适配器版本和源码哈希。

## 成交比较

解析 MT5 报告的“成交（Deals）”表，排除 `balance` 等非交易流水。PXY 成交先映射为
统一字段，再逐行比较：

1. 时间（`time`）；
2. 交易品种（`symbol`）；
3. 买卖方向（`side`）；
4. 进出场类型（`entry`）；
5. 交易量（`volume`）；
6. 成交价格（`price`）；
7. 手续费（`commission`）；
8. 库存费（`swap`）；
9. 单笔盈利（`profit`）；
10. 结余（`balance`，双方都有时比较）。

不得按时间或票号重新排序来掩盖同一 Tick 内的执行顺序差异。成交数量不同即失败，
报告必须给出第一处分歧及有限数量的后续差异。

默认只允许货币字段 `0.005` 的半分舍入差；时间、价格和手数默认零容差。
若某个品种需要按报价位数设置价格容差，测试向量必须显式记录，不能全局放宽。

## 验收层级

- L0 数据一致：Tick 数量、首尾时间、Bid/Ask、flags、volume 一致。
- L1 信号一致：策略在每个 Tick 的状态转换和下单意图一致。
- L2 成交一致：本契约全部字段通过。
- L3 账户一致：余额、净值、保证金、可用保证金和强平路径一致。
- L4 可视化一致：界面只降频刷新，不丢完整历史；暂停、继续、取消不改变 L1-L3。

只有 L0-L4 全部通过，才可以对该“EA + 参数 + 品种 + 时间 + 账户规格”测试向量标记
为 MT5 一致。通过一个测试向量不代表任意 MQ5 已被兼容。

命令行验收：

```powershell
python -m app.mt5_parity `
  --mt5-report <strategy-tester-report.htm> `
  --pxy-result <pxy-result.json>
```

完全一致时退出码为 0；存在任意成交数量或字段差异时退出码为 1，并输出结构化差异。
